# Changelog

All notable changes to this project are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project has not yet reached a first release, so everything so far is under `Unreleased`.

## [Unreleased]

### Added

- Solution scaffolding: `.slnx`, five-project Clean Architecture (`Domain`/`Application`/`Infrastructure`/`Presentation`/`Host`), `Directory.Build.props` enforcing nullable reference types and mandatory XML doc comments on public API
- Test suite foundation: `UnitTests` (xUnit), `BehaviorTests` (Reqnroll + `WebApplicationFactory`), `ArchitectureTests` (NetArchTest, mechanically enforcing the Clean Architecture boundary), and standalone fixture repositories (`PassingFixture`/`FailingFixture`/`HangingFixture`/`GitFixture`) for BDD scenarios to run real `dotnet`/`git` commands against
- Bearer authentication: constant-time credential comparison, shared by the MCP server and the dashboard (exchanged for an auth cookie via a login page)
- Path confinement: caller-supplied working directories are canonicalized, symlink-resolved, and confined to a configured root directory; file transfer applies the same policy twice (root→repository, then repository→file)
- Command execution (`dotnet_run`/`git_run` MCP tools): starts a `dotnet`/`git` command and returns a run id immediately; the caller polls `read_run_output` for incremental stdout/stderr and the eventual exit code, with a caller-overridable execution timeout (clamped to a configured maximum) and an output size cap. No subcommand/flag allowlist for `git_run`
- Per-repository concurrency locking: commands against different repositories run in parallel; a second command against a repository that already has one in flight is rejected with the conflicting run's id, not queued — shared bidirectionally between `dotnet_run`/`git_run`/`clone_repository`
- Cancellation (`cancel_run` MCP tool): one tool for any in-flight run (including a repository clone), killing the full process tree
- File transfer (`transfer_file` MCP tool): returns a file's contents (base64-encoded) confined to the named repository's own directory (any file, not just build output), size-capped since a tool result is a single response payload
- SQLite-persisted run history (via EF Core) for every run kind, including full-duration CPU/RAM time series per run, surviving service restarts with startup reconciliation of interrupted runs, filterable/searchable across kind/outcome/repository
- Repository management: list/clone/delete of repositories under the configured root, with live git-status (branch, dirty/clean, ahead/behind, and a distinct "remote gone" state when a tracking branch's remote-side branch has been deleted) sampled on a fast background cadence and total size on a separate, slower one; list and clone are also reachable as MCP tools (`list_repositories`, `clone_repository`, the latter accepting an optional initial branch) so the sbx caller can query and provision repositories itself — deletion and everything below stay dashboard-only, since giving the sbx caller that access risks misuse
- Repository detail page: clone source URL (from run history) and full remote list, plus a branch-switch dropdown (local + remote-tracking) that auto-creates a local tracking branch when switching to a remote-only branch
- Per-repository pull/push/force-push/fetch/clean (`git clean -xdf`) actions from the Repositories list — force-push and clean require an explicit popup confirmation; none of the five stream output, reporting only success/failure via a brief icon color flash
- Clone dialog branch selection: once a source URL is entered, remote branches are enumerated (`git ls-remote --heads`) and offered as a dropdown
- Repository detail commit graph: a branch-aware, lane/connector commit graph (most-recent-first, paginated) with branch/tag pills on the commits that carry them, and a checkout-as-detached-HEAD action per commit; detached HEAD is now distinguished from a real branch wherever git status is shown, instead of showing the literal ref name `HEAD`
- Repository detail file tree browser: an Explorer-style expandable/collapsible tree rooted at the repository, with download/rename/delete per file or folder (delete confirmed, rename inline); a new cookie-authenticated `GET /dashboard-files/{name}` endpoint backs downloads, separate from the bearer-token API surface
- Repository detail's Commits and Files sections live in a tab group (only one visible at a time)
- Blazor Server dashboard: dark-mode-only, bearer-token login, Status/History/Repositories top-level views plus routable run-detail/repository-detail subpages, a spawned-process list scoped to each run's own process tree with a kill action, history/repository filter and free-text search
- Icon-based dashboard controls (vendored from Lucide, ISC-licensed) replacing every text-labeled list/row button; destructive-action confirmation and the clone form are both native popup dialogs rather than an in-place button state change or an inline-revealed section
- Host and per-process resource monitoring (`PerformanceCounter`/WMI): host-level CPU/RAM plus per-process CPU/RAM for every process in a run's tree
- Live and historical performance graphs (vendored Chart.js): a rolling window during a run, the full persisted series afterward
- Transport hardening: HTTPS-only Kestrel (the service refuses to start on a plain-HTTP endpoint)
- Product branding: a logo (terminal-prompt `>` chevron on an orange-to-pink gradient), applied consistently across the installer (icon, banner/dialog art, bootstrapper logo) and the dashboard (favicon, header/login logo, accent color, run-kind badge colors)
- WiX Toolset installer: a Burn bootstrapper (`OutOfTheBoxSetup.exe`) chaining a hash-verified .NET 10 SDK and Git for Windows ahead of the MSI; the MSI creates a dedicated least-privilege service account, registers the Windows Service with SCM crash-recovery, opens a firewall rule, and natively supports upgrade/uninstall while structurally preserving the data directory (config + SQLite file) across both; an interactive config page (repository root, bearer token, port) with an auto-generated, upgrade-preserved, operator-overridable bearer token and service-account password, version display (including "upgrading from vX.Y.Z" on upgrades), and a dark theme on its two fully-owned dialog pages within native MSI's real styling limits
- Application-wide error logging (Serilog): a size/age-capped rolling log file in the data directory (`logs/outofthebox-.log`, daily rolling, 10 MB cap, 14-day retention), plus console output; `Error` for failed operator-triggered actions (run/transfer/clone/branch-switch/checkout process-start failures, delete/rename failures, kill-scope WMI failures) and `Warning` for internal-helper failures that degrade gracefully, across every layer of the codebase
- An MCP server (`/mcp`, MCP Streamable HTTP transport, official `ModelContextProtocol`/`ModelContextProtocol.AspNetCore` SDK): this service's sole sbx-facing interface (alongside the dashboard), exposing command execution, file transfer, repository list/clone, and Windows-specific diagnostics as ten self-describing typed tools (`dotnet_run`, `git_run`, `read_run_output`, `cancel_run`, `transfer_file`, `list_repositories`, `clone_repository`, `get_run_resources`, `get_environment_info`, `get_file_lock_info`) — no client-side skill/doc dependency needed to call it. Long-running commands are start-then-poll (`read_run_output`), not blocking or streamed, since MCP tool calls are fundamentally request/response. See [`openspec/changes/archive/2026-08-09-sbx-mcp-server/`](openspec/changes/archive/2026-08-09-sbx-mcp-server/) for the original design rationale
- `get_run_resources` MCP tool: a run's recent CPU/RAM trend (from the trailing ~10-minute window) plus a derived summary - latest CPU%, peak CPU% in the window, and idle-seconds - so a caller can judge whether a still-running `dotnet_run`/`git_run`/`clone_repository` is hung or just slow, instead of guessing from silence in `read_run_output`
- `get_environment_info` MCP tool: this host's installed dotnet/git versions (reusing the same provider behind the dashboard's Status tiles), installed .NET SDKs, installed .NET workloads (best-effort - never fails the call), configured NuGet package sources, and available disk space on the configured root directory's drive - computed fresh on every call, not cached, to diagnose a restore/build failure caused by an environment mismatch rather than a code problem
- `get_file_lock_info` MCP tool: which process(es) currently have a named file open (process id, application name, restartability), via the Windows Restart Manager API (`rstrtmgr.dll`, the same mechanism behind Explorer's own "this file is open in..." dialog) - diagnoses a Windows "file in use" build/test failure, which has no Linux analogue an sbx agent would already know to suspect
- Repository detail commit graph rewrite: one continuous multi-branch SVG overlay (not per-row), correctly rendering forks/merges with curved connectors, highlighting the checked-out commit and merge/fork points, and a routable commit detail page (`/repository-management/{name}/commits/{hash}`) reachable by clicking a commit row, showing full metadata, parent links, and changed files
- Branch checkout directly from a commit's ref pill in the commit graph, and repository/commit-log columns sized to their content instead of fixed widths
- Downloadable HTTPS certificate: the installer now writes a public-only, PEM-encoded `outofthebox.cer` (no private key) alongside the existing password-protected `outofthebox.pfx`, offered for download from the About page (`GET /dashboard-certificate`, cookie-authenticated) with detailed instructions for trusting it both on a Windows PC (import into Trusted Root Certification Authorities) and in the sbx sandbox (system-wide trust, `NODE_EXTRA_CA_CERTS`, or a one-off `curl --cacert` check) — previously an operator had to extract the public certificate from the PFX by hand

### Changed

- Flattened `src/` and `tests/` project directories (removed the layer-name/test-type wrapper folders, e.g. `src/Domain/OutOfTheBox.Domain/` → `src/OutOfTheBox.Domain/`); the `.slnx` no longer has per-layer solution folders, only a single `Tests` folder grouping the test projects
- Adopted Central Package Management (`Directory.Packages.props`) for third-party package versions (the `installer/` tree opts out, since WiX's own package versioning conventions don't fit CPM cleanly)
- Adopted the .NET SDK's centralized artifacts output layout: every project under `src/`/`tests/` (including `tests/Fixtures/`) builds into a single `artifacts/` directory at the repo root instead of a per-project `bin/`/`obj/` pair
- `.editorconfig` expanded from formatting-only conventions to a curated set of modern-C#-construct style rules (pattern matching, target-typed `new`, collection expressions, readonly/accessibility modifiers, unused usings/parameters, ...), enforced at `warning` severity and surfaced during `dotnet build`
- Renamed the project from `BuildAndTestService` to `OutOfTheBox`
- Replaced the originally-planned `install.ps1`/`upgrade.ps1` scripts with the WiX Toolset installer above, on explicit request — native upgrade/uninstall semantics and a proper config UI a hand-rolled script couldn't match

### Fixed

- Repository stats silently stopping forever after computing once at startup: a `git.exe` invocation failure (e.g. unreachable for the service account's PATH) inside the background stats sampler was left uncaught, which - since an unhandled exception in a `BackgroundService` stops the entire host by default - could silently kill the whole service, not just the sampler. One repository's stats computation failing can no longer affect any other repository or the sampler itself, let alone the host
- The page-title underline (Status/History/Repositories and their detail subpages) now tracks the heading text's actual width instead of a fixed 44px unrelated to the text
- A repository's stats could still, in one remaining shape, silently fail to refresh after a successful clone, pull/push/force-push/fetch/clean, branch switch, or commit checkout - none of the four immediate post-action stats refreshes had an exception guard, and the clone path's (a fire-and-forget continuation) additionally skipped its own completion signal on failure. All four now share one guarded refresh helper; this subsystem also gained its first application-level logging (`ILogger<T>`, surfaced via the Windows Event Log when hosted as a service) so a future occurrence is diagnosable without reading code
- The host/process resource sampler (`HostResourceSamplerService`) had the same unguarded-`BackgroundService`-tick bug as the repository stats sampler above: a single failed sampling tick (its `PerformanceCounter`/WMI dependencies are at least as fragile in the wild) would have silently killed the entire host, not just resource monitoring. Now caught and logged per tick instead of propagating
- Repository stats could get stuck reading "Computing…" forever after a clone completed, and, separately, changes to a repository's stats made in the background sampler weren't pushed live to an open dashboard session the way an immediate post-action refresh already was - both now update live
- Service-account SID resolution during the install-time repository-root ACL grant, root-caused to LSA cache lag rather than scheduling or impersonation (an earlier retry-loop workaround for the same symptom was removed once the real cause was known)
- The commit graph's SVG overlay could drift out of sync with its table (a row's content, e.g. a ref pill or the checkout button, could silently render taller than the overlay's fixed row-height assumption); dots are now reliably centered on their row, the newest commit's line no longer extends above its own dot, and fork/merge connectors now terminate exactly at the relevant commit's dot instead of a row edge, colored by the lane they actually represent
- Clicking a commit's parent-hash link on the commit detail page updated the URL but kept showing the previous commit's data - Blazor reuses the component instance across same-route navigations, so the data reload was moved from `OnInitializedAsync` (runs once per instance) to `OnParametersSetAsync` (runs on every navigation)
- The About page's MCP tool list was missing `get_run_resources`, `get_environment_info`, and `get_file_lock_info`, and still said "eight tools"
